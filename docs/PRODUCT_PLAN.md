# 理发店管理系统 — 产品方案

## 1. 产品概述

一套面向中小型理发店/美发沙龙的 **SaaS 多租户管理系统**，帮助店铺老板实现数字化经营，覆盖会员管理、服务管理、收银结算、员工服务统计、营收分析等核心业务场景。一套系统可同时服务多家理发店，各店数据完全隔离。

### 1.1 目标用户

| 角色 | 核心诉求 |
|------|----------|
| 平台管理员 | 管理所有租户店铺、License 分发、平台级数据总览 |
| 店铺老板（店主） | 掌握经营全貌、会员资产、营收数据、员工服务情况 |
| 店长/前台 | 日常开单收银、会员办理 |
| 发型师/技师 | 查看个人服务记录 |

### 1.2 产品定位

- 轻量级、上手快，前台 10 分钟学会开单
- B/S 架构，浏览器即用，手机/Pad/电脑全端覆盖
- 响应式适配，无需安装 App 或小程序
- 多租户架构，每家店铺独立数据空间
- 按功能模块分级定价

## 2. 功能模块设计

### 2.1 会员管理

#### 会员档案

| 字段 | 说明 |
|------|------|
| 基础信息 | 姓名、手机号、性别、生日、头像 |
| 会员卡号 | 系统自动生成，支持自定义规则 |
| 会员等级 | 店主手动指定，关联等级折扣 |
| 账户余额 | 充值卡余额（含赠送金额） |
| 次卡剩余 | 购买的次卡及剩余次数 |
| 消费记录 | 历史服务、充值、退款流水 |
| 偏好标签 | 喜好发型、指定发型师、过敏信息等 |
| 备注 | 发型师/前台可添加客户备注 |

#### 会员等级体系

店主可完全自定义等级名称和对应折扣，系统不预设任何等级，所有等级由店主按需创建和管理。

**等级配置项：**

| 配置项 | 说明 |
|--------|------|
| 等级名称 | 自由命名，如：普通会员、银卡、金卡、钻石、VIP 等 |
| 折扣比例 | 0.1 ~ 1.0，消费时自动按此折扣计算 |
| 等级排序 | 排定等级高低顺序，用于展示和筛选 |
| 备注 | 内部备注，如"充值满 500 自动调整为此等级" |

**配置示例（店主自定义）：**

```
┌──────┬──────────┬────────┬──────────────────────┐
│ 排序  │  等级名称  │  折扣   │  备注                 │
├──────┼──────────┼────────┼──────────────────────┤
│  1   │  普通会员  │  无折扣  │  默认等级              │
│  2   │  银卡     │  9.5 折  │  店主手动调整           │
│  3   │  金卡     │  8.8 折  │  店主手动调整           │
│  4   │  钻石卡    │  8 折    │  店主手动调整           │
│  5   │  至尊VIP   │  7.5 折  │  店主手动调整           │
└──────┴──────────┴────────┴──────────────────────┘
```

**等级调整方式：**

- 店主/店长手动为会员指定等级
- 前台收银时可即时调整
- 不存在自动升降级逻辑

#### 会员标签与分群

- 系统标签：新会员、沉睡会员（90天未到店）、VIP、高消费
- 自定义标签：支持店主自定义标签分组
- 智能分群：按消费频率、客单价、最近到店时间自动分组
- 群发触达：基于分群发送短信/微信模板消息

### 2.2 充值管理

#### 充值方案

店主可配置多种充值方案，引导客户多充多送：

| 充值方案类型 | 示例 |
|-------------|------|
| 直充 | 充 500 元到账 500 元 |
| 充赠 | 充 1000 送 100，充 2000 送 300 |
| 阶梯赠送 | 充 500 送 5%，充 1000 送 8%，充 3000 送 15% |
| 限时活动 | 国庆双倍赠送、新店开业充值特惠 |

#### 账户体系

```
会员账户
├── 储值余额（本金）     ← 充值金额，可退
├── 赠送余额           ← 活动赠送，不可退，消费时先扣
├── 次卡               ← 购买的服务次数包
│   ├── 剪发 10 次卡    剩余 7 次  有效期至 2026-12-31
│   └── 烫染 5 次卡     剩余 3 次  有效期至 2026-09-30
└── 优惠券             ← 满 200 减 30 等
```

#### 充值流水

每笔充值生成独立流水记录，包含：

- 充值时间、操作人、会员信息
- 充值金额、赠送金额、赠送原因
- 支付方式（现金/微信/支付宝/银行卡）
- 关联活动（如有）
- 备注

### 2.4 收银开单

#### 开单流程

```
客户到店
  │
  ▼
查询/新建会员 ◄── 扫码/手机号/姓名
  │
  ▼
选择服务项目 + 指定服务员工
  │
  ├── 可选多个项目
  ├── 每个项目可指定不同服务员工
  └── 添加备注/偏好
  │
  ▼
服务完成确认
  │
  ▼
结算方式
  ├── 余额支付（扣储值卡）
  ├── 次卡核销（扣次数）
  ├── 线下支付（客户通过微信/支付宝/现金等自行付款，系统仅记录）
  ├── 混合支付（余额 + 线下补差）
  └── 优惠券抵扣
  │
  ▼
打印小票 / 电子回执
```

#### 结算规则

- **本金与赠送扣减顺序**：先扣赠送余额，再扣本金
- **次卡核销**：对应服务项目扣减 1 次，过期不可用
- **线下支付记录**：客户通过微信转账、支付宝、现金等任意方式自行付款后，前台在系统中选择"线下支付"并记录支付方式，系统仅做数据记录，不涉及实际资金流转
- **折扣叠加**：会员折扣与优惠券可配置是否叠加
- **挂单**：服务进行中可挂单，完成后结算
- **退单**：当日可撤销，隔日走退款审批

#### 支付方式说明

| 模式 | 说明 | 资金流向 |
|------|------|---------|
| 余额支付 | 从会员储值卡扣减 | 系统内扣减，资金已在充值时到账 |
| 次卡核销 | 扣减次卡剩余次数 | 系统内扣减，资金已在购卡时到账 |
| 线下支付（记录） | 客户通过微信/支付宝/现金等自行付款给店铺 | 资金直接到店主账户，系统仅记录金额和支付方式 |

> 系统不集成第三方支付通道，不处理实际资金流转。所有非余额支付均由客户和店主在线下自行完成，系统只负责记录支付事实以保证营收数据完整。

### 2.8 多租户与平台管理

系统为 SaaS 多租户架构，一套系统服务多家理发店，各店数据完全隔离。

#### 平台管理员

| 功能 | 说明 |
|------|------|
| 店铺管理 | 创建/查看/停用租户店铺 |
| License 分发 | 为各店铺分配授权，管理版本和有效期 |
| 平台总览 | 全平台店铺数、活跃店铺、总营收趋势 |
| 使用监控 | 各店铺活跃度、数据量、License 到期预警 |
| 平台设置 | 全局通知配置、定价策略、支付通道（如有） |

#### 租户数据隔离

- 每个店铺拥有独立的 `shopId`，所有业务数据按 `shopId` 隔离
- API 层强制注入 `shopId` 过滤，店铺无法访问其他店铺数据
- 员工登录后自动绑定所属店铺，只能看到本店数据
- 平台管理员可跨店查看汇总数据

#### 多租户登录流程

```
员工打开系统
  │
  ▼
选择所属店铺（或通过子域名/专属链接自动识别）
  │
  ▼
输入手机号 + 密码登录
  │
  ▼
系统校验
  ├── 员工属于该店铺
  ├── 店铺状态正常（未停用）
  └── License 有效
  │
  ▼
进入该店铺的管理界面

---

平台管理员
  │
  ▼
专属管理后台 (/platform)
  │
  ▼
查看/管理所有店铺
```

## 3. License 管理设计

### 3.1 授权模型

```
┌──────────────────────────────────────────────────────────┐
│                    License 授权体系                        │
├─────────────┬──────────────────┬────────────────────────┤
│   免费版     │    专业版         │      旗舰版             │
│   Free      │    Pro           │      Enterprise         │
├─────────────┼──────────────────┼────────────────────────┤
│ 2 员工账号   │ 10 员工账号      │ 不限员工数              │
│ 基础收银     │ 全功能           │ 全功能 + 定制化          │
│ 会员 ≤ 200  │ 会员不限         │ 会员不限                │
│ 简单报表     │ 完整数据分析      │ 高级BI + 数据导出        │
│ 社区支持     │ 在线客服         │ 专属客户经理             │
├─────────────┼──────────────────┼────────────────────────┤
│ 免费        │ ¥99/月/店        │ ¥299/月/店              │
│             │ ¥999/年/店       │ ¥2999/年/店             │
└─────────────┴──────────────────┴────────────────────────┘
```

### 3.2 License 技术实现

```
License 签发流程：

  店主付费（平台管理员操作或自助）
    │
    ▼
  平台生成 License Key
    │
    ├── 绑定：店铺 ID + 版本 + 过期时间 + 模块权限 + 员工数上限
    │
    ▼
  写入 License 数据库
    │
    ▼
  店铺端登录时自动拉取 License
    │
    ├── 本地缓存 License 信息
    ├── 每次启动校验签名与有效期
    ├── 定期（每日）心跳校验
    └── 离线容忍期：3 天（断网可继续使用 3 天）
```

```json

  "plan": "pro",
  "staff_limit": 10,

  "modules": ["pos", "member", "service", "analytics"],
  "issued_at": "2026-05-17T00:00:00Z",
  "expires_at": "2027-05-17T23:59:59Z",
  "features": {
    "data_export": true,
    "sms_notification": true,
    "api_access": false
  },
  "signature": "RSA-SHA256签名..."
}
```

### 3.3 功能门控策略

```
用户操作
  │
  ▼
Feature Gate 拦截
  │
  ├── 读取本地缓存的 License
  │
  ├── 校验签名有效性
  │
  ├── 检查模块权限（modules 字段）
  │
  ├── 检查数量限制（staff_limit / members_limit）
  │
  ├── 检查到期时间
  │
  ▼
  ├── 通过 → 放行
  │
  └── 不通过 →
       ├── 模块未授权 → "该功能为专业版及以上功能，请升级"
       ├── 数量超限   → "已达当前版本上限（10人），升级旗舰版不限人数"
       └── 已过期     → "授权已过期，请续费后继续使用"
                         （基础收银功能保留 7 天宽限期）
```

### 3.4 到期与续费处理

| 阶段 | 系统行为 |
|------|---------|
| 到期前 15 天 | 系统通知（短信+站内信），数据面板显示续费提醒 |
| 到期前 3 天 | 每日弹窗提醒，不打断正常操作 |
| 到期日 | 降级为免费版功能，历史数据保留只读 |
| 过期 30 天 | 数据归档，保留 90 天可恢复 |
| 续费后 | 即时恢复对应版本功能 |

## 4. 典型业务场景与流程

### 场景一：新客户到店消费

```
客户进店
  │
  ▼

  │
  ├── 有会员 → 输入手机号查询 ──► 找到会员档案
  │                                      │
  └── 无会员 → 引导注册                  │
        │                                │
        ▼                                ▼
  输入手机号 + 姓名                  确认会员信息
        │                                │
        ▼                                │
  选择是否充值 ◄── 推荐首充优惠           │
        │                                │
        ├── 充值 → 选择充值方案            │
        │       → 支付                   │
        │       → 会员卡激活              │
        │                                │
        └── 不充值 → 注册为普通会员        │
                                         │
                                         ▼
                                   选择服务项目 + 服务员工
                                         │
                                   ▼
                                   开始服务
                                         │
                                   服务完成 → 前台确认
                                         │
                                         ▼
                                    结算
                                   ├── 余额支付
                                   ├── 线下支付（记录）
                                   └── 次卡核销
                                         │
                                         ▼
                                   打印小票 / 电子回执
                                         │
                                         ▼

```

### 场景三：多项目混合结算

```
客户：金卡会员，余额 ¥800
服务：剪发 ¥80（张师傅）+ 染发 ¥180（李老师）+ 护理 ¥120（张师傅）= ¥380
金卡折扣：8.8 折 → 实付 ¥334.4

结算过程：
  │
  ▼
系统计算
  ├── 原价合计：¥380
  ├── 金卡折扣：-¥45.6
  ├── 应付金额：¥334.4
  │
  ▼
客户选择支付方式
  │
  ├── 方案A：全余额支付
  │   扣余额 ¥334.4（先扣赠送 ¥50 → 再扣本金 ¥284.4）
  │   剩余余额：¥465.6
  │
  ├── 方案B：余额 + 线下支付组合
  │   客户要求只扣 ¥200 余额
  │   余额扣 ¥200 → 客户自行微信转账 ¥134.4 → 系统记录"线下支付"
  │
  └── 方案C：使用优惠券
      有满 300 减 30 券
      ¥334.4 - ¥30 = ¥304.4
      再选择余额或线下支付
  │
  ▼
确认支付 → 生成订单
  ├── 扣减余额/次数
  ├── 核销优惠券
  ├── 记录线下支付金额及支付方式
  ├── 记录各项目服务员工（剪发→张师傅、染发→李老师、护理→张师傅）
  └── 更新会员消费记录
```

## 6. 技术架构建议

### 6.1 整体架构

```
┌───────────────────────────────────────────────────┐
│                 响应式 Web 应用                     │
│  ┌──────────────────────────────────────────────┐ │
│  │              Next.js (统一前端)                │ │
│  │  管理后台（桌面优先）  │  前台收银（手机优先）   │ │
│  │  平台管理（桌面）      │                       │ │
│  └──────────────────────┬───────────────────────┘ │
└─────────────────────────┼─────────────────────────┘
                          │
                          ▼
┌───────────────────────────────────────────────────┐
│                  API Gateway                       │
│            (认证 / 限流 / 租户隔离 / 路由)          │
└───────────────────────┬───────────────────────────┘
                        │
                        ▼
┌───────────────────────────────────────────────────┐
│             NestJS (单体模块化 + 多租户)             │
└───────────────────────┬───────────────────────────┘
                        │
       ┌────────────────┼────────────────┐
       ▼                ▼                ▼
┌────────────┐   ┌──────────┐    ┌────────────┐
│ PostgreSQL  │   │  Redis   │    │   OSS/S3   │
│ (主数据库)   │   │  (缓存)   │    │ (文件存储)  │
└────────────┘   └──────────┘    └────────────┘
```

### 6.2 技术选型建议

| 层次 | 推荐方案 |
|------|---------|
| 前端（全端统一） | Next.js + shadcn/ui + Tailwind CSS，响应式适配桌面/手机/Pad |
| 后端 API | Node.js (NestJS)，内置多租户中间件 |
| 数据库 | PostgreSQL，共享数据库 + shopId 隔离 |
| 缓存 | Redis |
| 支付记录 | 线下支付方式标签 + 金额记录，不集成支付通道 |
| 部署 | Docker + 云服务器 |
| License 服务 | 内置模块，RSA 签名校验 |

## 7. 数据安全与合规

| 要求 | 措施 |
|------|------|
| 租户隔离 | API 层强制 shopId 过滤，禁止跨店数据访问 |
| 会员隐私 | 手机号脱敏显示、数据加密存储 |
| 支付安全 | 系统不处理实际资金流转，仅记录线下支付数据 |
| 数据备份 | 每日自动备份、支持异地容灾 |
| 操作审计 | 关键操作（充值/退款/权限变更）全程记录 |
| 权限控制 | 基于角色的细粒度权限（RBAC） |
| 合规 | 遵守个人信息保护法、网络安全法 |
